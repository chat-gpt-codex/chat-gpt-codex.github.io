What chat gpt codex is now

The name has moved twice, which is why the search results are confusing. Codex started in April 2025 as a coding agent for developers. In February 2026 OpenAI shipped the Codex app for macOS, described as a command center for agents rather than a chat window: you run several agents in parallel, each on its own task, and supervise work that can span hours. Windows support followed on 4 March 2026. The same agent is also reachable from inside ChatGPT, from the CLI, from an IDE extension and from the cloud, and OpenAI states that your rate limits apply across all of those surfaces rather than per tool. By July 2026 the company said more than five million people use Codex every week, and that more than a million of them use it for work that is not software at all.

Which plan gets you in

When the app launched, OpenAI said it was including Codex with ChatGPT Free and Go for a limited time, and doubling rate limits on Plus, Pro, Business, Enterprise and Edu. Those higher limits follow the account, so the same subscription covers the app, the CLI, the IDE plugin and cloud runs. Two things follow from the wording. First, free access is a promotion with no stated end date, so a workflow built on it can become a paid workflow without warning. Second, the useful comparison between tiers is not features but headroom, because every surface draws from the same allowance. A per-plan breakdown lives on the Codex pricing page, and the developer documentation sits on the OpenAI developers site rather than in the consumer help centre.

Skills, automations and parallel agents

Three capabilities distinguish the app from a chat session. Skills extend the agent past code generation, so it can be pointed at work that has a repeatable shape. Automations take repetitive jobs off your hands on a schedule rather than waiting for a prompt. Parallel agents let you start several tasks at once and check them like a build queue, which changes the unit of work from a message to a job. There is also a configurable personality setting, which sounds cosmetic and is not: an agent that asks fewer questions behaves very differently on a long task. OpenAI describes the security posture as secure by default and configurable by design, which in practice means sandboxing and approvals you can loosen deliberately rather than by accident.

Who is running it in production

The Codex page lists Heidi, NVIDIA, Cisco and Shopify among the teams using it, which tells you the target is a working engineering organisation with review processes, not a weekend project. That framing matters when you evaluate it. An agent that opens pull requests is only as useful as the review culture around it, and the pitch is explicitly about routine pull requests scaling into larger engineering work. If you have no repository, no CI and nobody to review a diff, most of what Codex is good at has nowhere to land. The July 2026 announcement of ChatGPT Work, which has Codex technology built in, points the other way: the same engine aimed at documents, sheets and slides for people who never open a terminal.

When a coding agent is the wrong tool

There is a category of request that looks like programming and is really assembly: a landing page, a small marketing site, a copy of a layout you already like, a simple mobile app to hand to a client. Codex will do it, and then you still own the repo, the build step and the hosting decision. Begin.sh takes the other route. You give it a prompt, or a URL to clone, and it returns a working static site or an Expo app as a zip you download. No hosting, no backend, no auth, which is a real limitation if you need accounts or a database and exactly the point if you do not. Use the agent for the codebase you maintain, and the generator for the artefact you just want to exist.

Is Codex the same as the old Codex model?

No, and this trips people up constantly. The original Codex was a model from an earlier generation. What ships under the name today is an agent product: it edits files, runs commands, opens pull requests and manages long tasks across the app, CLI, IDE and cloud.

Do I need the desktop app?

No. The same agent is reachable inside ChatGPT, from the CLI, from an IDE extension and in the cloud. The macOS app arrived on 2 February 2026 and Windows on 4 March 2026, and its advantage is supervising several agents in parallel rather than any exclusive capability.
